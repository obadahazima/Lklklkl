# Opening balance snapshots and historical transactions

An account can store an optional openingBalanceDate (local YYYY-MM-DD). Transactions strictly before this date are automatically considered included in that account opening balance. Same-day and later transactions retain normal cash effects unless explicitly marked included. Comparison uses calendar dates, not creation timestamps. Existing accounts retain null dates, and existing transactions retain false flags.

Each transaction can explicitly mark includedInOpeningBalance. When true, the source/account cash effect is skipped. A transfer has a separate destinationIncludedInOpeningBalance flag for its destination, since the two entered balances may reflect different histories. Financial reports, revenue/expense classification, dates and receivable allocation links remain intact. Changing a collection's cash-inclusion flag does not repay or reopen any debt.

The web supports account dates and inclusion choices in manual entry, voice review, transaction editing, cold offline entry and receivable collections. Native source supports the same forms and a creation date for accounts. Inclusion choices persist in drafts/outbox, are sent as booleans and survive backup/restore. Resetting an entry or parsing new speech clears old choices. Transactions before a known snapshot date display a checked, locked automatic-inclusion control. This is derived from the current account/date, never stored as a manual choice, so changing the date or account recalculates it. Accounts without dates still allow explicit inclusion, avoiding guesses about historical balances.

For an account with an opening date, historical transactions strictly before it are automatically included when the balance is recalculated. For same-day entries or an account without a date, the manual inclusion checkbox remains available. Do not delete the historical expense or add a fake income.

Deploy the API first. Startup adds nullable accounts.opening_balance_date and non-null false-default transaction inclusion flags in an idempotent, advisory-locked migration. There is no guessed date/backfill: accounts without an opening date keep their previous cash behavior. Setting or changing a snapshot date recomputes automatic inclusion of historical rows. AI account context uses the same flags; chat creation uses automatic inclusion for earlier dates and asks about same-day ambiguity.
